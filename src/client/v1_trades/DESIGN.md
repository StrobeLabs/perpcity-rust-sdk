# `v1_trades`: the `v1.0.0` taker writes

Up: [`client`](../DESIGN.md). Each write refuses another build after the era read, carries a deadline `V1_TRADE_DEADLINE` after the signing time and a `maxTotalFee`, and returns the receipt's parsed event from [`events::receipt`](../../events/DESIGN.md), so no `v1.0.0` taker write reports success without its event. A replacement has a strictly later deadline. At the maximum deadline, the SDK refuses to replace a pending trade.

## Accepted structure

The writes take the earlier builds' exact parameters (`ExactOpenTakerParams`, `ExactAdjustTakerParams`) and add the `v1.0.0` fields as arguments, so those structs and their callers are unchanged. The fee bound is a volume, not a rate: the caller knows the trade's USDC leg and the market knows the rates, which are read with the fees module address at one pinned head block for each volume-based write. The close takes an explicit fee bound from the caller. The reduce-only check reverses the stored amount in `I256`, and close checks that the result fits `PerpDelta` before sending.

The replacement is a client method and not a pipeline step: the pipeline's send waits for one hash, and a replacement must poll two. It runs only after that send returned, which `TxPipeline::is_in_flight` checks, and it is not recorded in the pipeline, because it reuses a nonce the pipeline has already counted. One private helper, `replace_v1_trade`, does the replacement for any `v1.0.0` call a decoder reads, so every write family gets the same error classes. The helper does not trust the node's answer to the look-up, because it signs that answer's call again with the client's key: the signed fields must hash to the hash asked for (else `UnknownToNode`), and the signature must recover to the client (else `WrongSender`); the node's `from` field is not used. Each check that settles the outcome reads the account nonce before the receipts. A failed receipt read is no answer. A nonce seen used with every receipt read answering "none" gets more looks (three when polling, one after a single check), because a round-robin or hedged transport can serve the nonce before the receipt; only then is it `TransactionError::ReplacementNonceUsed`, not a timeout. Every write classifies a failed era read by one rule: no answer (a timeout, a rate limit, a dropped connection, a server error) is `PerpCityError::Rpc` and transient; an answer (an execution revert of `poolKey()` or `poolId()`, or a refused method such as `-32601`) stays the read's error, not transient. A market of another build is refused as `ReplacementUnconfirmed` with the era error as its cause, so the given hash is kept. A mined failure is classified as a send's (`OutOfGas` with the estimate evicted, or `Reverted`). A failure that leaves the original pending is `TransactionError::ReplacementUnconfirmed`, with the original hash, its nonce, any replacement hash and the cause; its transience and revert class are the cause's. A refusal is `TransactionError::NotReplaceable` with a `NotReplaceableReason`, which says whether the original can still land. After an explicit rejection by the node on every attempt of the transport (`underpriced`, a fee or funds answer), the receipts are checked once, not until the timeout; `already known`, `nonce too low`, an unknown wording and a timeout are polled. The rejection list is the transport's (`transport::fault`), because the transport decides whether a rejection after its retries is still the node's answer. `TransactionError::hash_to_replace` names which hash to replace next, not whether to (`is_transient` says that); the caller keeps the earlier hashes only for the case where the node no longer knows the named one (`UnknownToNode`). The method keeps the name `replace_v1_taker`; an alias would add a second name for one concept.
